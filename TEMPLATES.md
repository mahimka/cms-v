# Шаблоны страниц: что выбрать и как заполнить

Шаблон (`/admin/page_templates`) описывает, **какие страницы** создать и **с каким текстом**. Страницы создаёт `PageTemplateGenerator` по кнопке **g** в списке шаблонов. Плейсхолдеры в полях (`{name}`, `[addressLocality.slug]`, `{parent.name}`…) описаны в `TEMPLATES_PARENT.md` и в начале `app/models/template_field_renderer.rb`.

## 1. Какой тип выбрать

| Нужна… | Тип | Пример |
|---|---|---|
| страница **одного объекта** (отель, пляж, город) | **Profile** | `/izola/beaches/bele-skale` |
| страница-**список** (пляжи Анкарана, отели Копера) | **List** | `/ankaran/beaches` |

Адрес страницы всегда считается как **адрес родителя + slug**. Задать произвольный uri нельзя: он выводится из цепочки родителей. Поэтому нужная страница-родитель должна уже существовать.

## 2. Profile — страница на каждый объект

**Какие объекты:** `pageable_type` (Entity/Item/Event/Picture) + `template_conditions` (теги) + `schema_id` (схема). Страницу получают объекты, у которых включён `generate_pages`.

**Где будет лежать страница** — один из двух способов:

1. **`parent_page_id` + `slug`** — все страницы под одним родителем. `slug` обычно `{name}`.
2. **`page_uri`** — полный путь, родитель у каждой страницы свой:

```
page_uri: /[addressLocality.slug]/beaches/{name}
→ /ankaran/beaches/valdoltra
→ /izola/beaches/bele-skale
```

Как читается `page_uri`:
- каждый сегмент — обычный текст с плейсхолдерами; последний сегмент становится slug страницы, остальные — путём к **уже существующей** странице-родителю;
- родитель ищется от корня сайта по **slug страниц** (не по uri), всё равно кто и как его создал: вручную, List-шаблоном или Profile-шаблоном;
- `[addressLocality.slug]` — первый тег этой группы у объекта (по `position`, потом по имени);
- можно усложнять последний сегмент: `{name}-beach`, `{name}-beach-[beach_features]`;
- если `page_uri` заполнен, `parent_page_id` и `slug` самого шаблона **игнорируются**.

Если для объекта не нашёлся родитель или тег — страница **не создаётся**, а причина показывается после генерации (первые 10). Объект сменил город — при следующей генерации его страница переезжает под нового родителя (даже без *force*), uri потомков и редиректы обновляются сами.

## 3. List — страница-список

List не привязан к объекту. Что показывает страница, задают `conditions` (теги) + `pageable_type` + `schema_id`.

### 3.1. Страница на каждое значение группы тегов

`slug` содержит блок группы:

```
slug: [addressLocality.slug]   →   /ankaran, /izola, /koper …
```

По странице на каждый тег группы, который встретился у объектов выборки. Родитель — `parent_page_id` (или корень).

**Ограничить, для каких тегов создавать:** включите чекбокс **only_marked_tags** — тогда страницу получают только теги с отметкой **gp** (`tags.generate_pages`, правится в `/admin/tags`). Так вы сами решаете, какие города получают страницу. Выключено — страница на каждое встреченное значение.

### 3.2. Подчинённый List — под каждой страницей родителя

Заполните `parent_template` — страницы будут созданы **под каждой страницей выбранного шаблона**, а не под одной `parent_page_id` (она тогда игнорируется).

**Родитель — List** (например, страны → регионы): страницы создаются под каждой страницей родителя; в `conditions` автоматически добавляется тег родителя.

**Родитель — Profile** (например, города как объекты → `/ankaran/beaches`): обязательно задайте **`parent_tag_group`** — группу, где лежит тег города (`addressLocality`). Тег ищется по совпадению slug (или имени) тега со slug страницы-родителя: страница `ankaran` → тег Ankaran. Нет тега — страница не создаётся, причина покажется после генерации. Найденный тег автоматически попадает в `conditions`.

**slug-слово.** В подчинённом шаблоне в `slug` можно написать просто слово (`beaches`) — тогда создаётся **одна страница под каждой страницей родителя**:

```
parent_template: #1 (города, Profile)    parent_tag_group: addressLocality
slug: beaches                            schema_id: Beach
→ /ankaran/beaches, /izola/beaches, /koper/beaches
```

Страница не создаётся, если у родителя нет подходящих объектов (нет пляжей в Анкаране — нет `/ankaran/beaches`).

## 4. Условия: теги и схема

Две пары полей, заполняйте одинаково:

- **`template_conditions`** — *для каких объектов* шаблон вообще создаёт страницы. Нет объектов — нет страницы.
- **`conditions`** (только List) — *что показывает* созданная страница. Для подчинённого шаблона тег родителя (Ankaran) добавляется автоматически — писать город не надо.
- **`schema_id`** — доп. фильтр по схеме (с поддеревом: Hotel входит в LodgingBusiness). Пусто — не фильтрует.

Формат тегов — строка или JSON-массив (теги по slug, а если slug у тега нет — по точному имени с учётом регистра):

| Нужно | Запись |
|---|---|
| один тег | `Beach` |
| все теги сразу | `["Beach", "Blue flag"]` (без оператора = `and`) |
| beach и (флаг 1 или флаг 2) | `["and", "Beach", ["or", "Blue flag", "Pier on beach"]]` |
| beach, но не с тегом X | `["not", "Beach", "X"]` (левое минус правое) |
| схема + тег | `schema_id = Beach`, в полях условий `Blue flag` |

Схема или тег: при `schema_id` страница сама получает в `conditions` фильтр по схеме. Без схемы `Beach` в условиях — обычный тег.

## 5. Как запускать

Порядок — от родителей к детям. Пример для курорта:

1. **Города** — Profile (по объектам City) или List (по тегам `addressLocality`).
2. **Списки под городами** — подчинённый List со `slug = beaches`.
3. **Сами пляжи** — Profile с `page_uri = /[addressLocality.slug]/beaches/{name}`.

Кнопки:
Кнопки в строке шаблона (`/admin/page_templates`), там же в `edit`:
- **g** — только создаёт недостающие страницы, существующие не трогает (кроме переезда под нового родителя у Profile с `page_uri`);
- **f** (force, с подтверждением) — обновляет поля существующих страниц по шаблону, ручные правки могут быть перезаписаны. Поля, которые админка пометила как отредактированные (`edited_columns`), не затираются; `ready`/`published` не меняются.

Результат: «создано / обновлено / пропущено (уже есть)» и, если что-то не получилось, «не создано N» с причинами.

`page_ready` / `page_published` у шаблона ставятся страницам **только при создании**. После этого публикуйте в админке страниц; неопубликованная страница отдаёт 404.

## 6. Частые ошибки

| Симптом | Причина |
|---|---|
| Страницы подчинённого List не создаются | у родителя нет страниц; для родителя Profile не задан `parent_tag_group`; нет объектов под условия |
| «нет страницы-родителя для /izola/beaches/…» | сначала создайте `/izola/beaches` (шаг 2) |
| «нет тега … в группе addressLocality» | тег города называется иначе, чем страница; проверьте slug страницы и slug/имя тега |
| «пустой сегмент» | у объекта нет тега группы из `page_uri` |
| Список страницы пуст, а объекты есть | `conditions` и `template_conditions` не совпадают; тег записан с другим регистром (**Blue flag** ≠ **blue flag**) |
| Дубли тегов | слить кнопкой merge в `/admin/tags`: сравнение по имени чувствительно к регистру |
| Страница получила slug с id (`/ankaran-2190`) | такой uri уже занят другой страницей; генератор добавляет город, страну, потом id |
| Адрес сменился после смены родителя | это нормально: потомки пересчитываются каскадом, старые адреса — редиректы в History |

## 7. Что не делает шаблон

- не создаёт промежуточные страницы пути сам — родитель должен быть;
- не переводит страницы (`translate:pages` — отдельно);
- не публикует страницы после создания.
